Button

Standalone interactive button. Three style families, three sizes, and an icon-only mode combine into 18 variants. Anatomy: LeftIcon · Label · RightIcon, centered horizontal flex. Label is hidden when IconOnly=true; in that mode the LeftIcon slot carries the single visible glyph.

Source: figma node 106:43 · spec: ./button.tokens.json

State model — documented but not built as variants

Hover and disabled bindings are recorded in button.tokens.json but not implemented as Figma variants. The hover state below uses the .is-hover modifier to render statically; disabled uses the native disabled attribute.

Tertiary hover is undefined in button.tokens.json (the style.tertiary.hover block is empty) — the rendered hover cell intentionally matches the default cell.

Secondary disabled background stays at the default token because no background/secondary/disabled semantic token exists. Only the foreground dims via text/primary/disabled.

Active state has no semantic token. The CSS uses filter: brightness(0.95) as a stopgap — try clicking and holding.

Code example

Markup pattern. Variant classes swap to change Style, Size, and IconOnly.

<!-- Style=primary, Size=md, IconOnly=false, both icons hidden -->
<button class="btn btn--primary btn--md">Button</button>

<!-- With leading icon -->
<button class="btn btn--primary btn--md">
  <span class="btn__icon"><svg ...></svg></span>
  Button
</button>

<!-- Icon-only (Size=md) -->
<button class="btn btn--primary btn--md btn--icon-only" aria-label="Action">
  <span class="btn__icon"><svg ...></svg></span>
</button>

<!-- Disabled -->
<button class="btn btn--primary btn--md" disabled>Button</button>

Known issues / gaps (from $notes)

states-not-built-as-variants — Hover and disabled bindings are recorded for downstream consumers but are NOT implemented as Figma variants. Only the default state of each (Style × Size × IconOnly) combination is rendered.

active-state-no-token — No semantic token covers the active/pressed state. Stopgap: filter: brightness(0.95). System-level gap.

icon-color-binding-gap — Audit returned colorVar: null for every LeftIcon and RightIcon across all 18 variants. The component-set description claims icon/primary/default (primary, secondary) and icon/brand/default (tertiary), but those bindings were not detected on the variant nodes. Re-binding pass recommended.

disabled-bg-gap-secondary-tertiary — Only background/brand/disabled exists. Secondary and tertiary disabled blocks intentionally omit a background alias.

tertiary-hover-undefined — Component-set description proposes background/brand/default as a tertiary hover treatment but no token authoritatively covers it. style.tertiary.hover is empty.

focus-state-empty — No focus-visible state implemented in the component. The doc page applies a generic outline as a placeholder for keyboard accessibility, but it is not driven by a token binding.

icon-only-visibility-detach — On IconOnly=true variants, LeftIcon/RightIcon have their visible componentPropertyReferences detached and visibility is hardcoded. Required because Figma boolean visibility properties are shared globally across variants of a set.
